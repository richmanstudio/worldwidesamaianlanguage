# Лексический аудит SAMA 0.2 → 0.3

Исходная выборка: **486** строк, **430** уникальных написаний. **18** форм имели несколько различающихся определений. Эти определения были проверены и редакторские решения сохранены в `content/legacy/resolved-conflicts.json`. Это не лингвистическая независимая экспертиза — только исправление внутренних противоречий.

Из 430 исходных форм **118** многословных и/или сложных сочетаний перенесены в `content/legacy/quarantine.json` как неподтверждённые. Они не удалены, но исключены из основного учебного словаря. Примеры:

| Исходная форма | Почему не подходит | Новый вариант |
|---|---|---|
| `selo` = олень | `selo` уже означает «другой» | `seli` — новый кандидат «олень» |
| `pala-doma` = старое здание | `pala` = четыре | `doma palae` (дома + качество «старый») |
| `pala-mato` = старое дерево | `pala` = четыре | `mato palae` |
| `mona-tima` = месяц | `mona` = кожа | `meya` — новый кандидат «календарный месяц» |
| `misa-nini` = маленькая птица | `misa` = ключ | `nini mini` |
| `soma-bona` = добрый человек | определение качества ошибочно записано через дефис | `soma bona` |
| `koma-toka` = онлайн-общение / общественная дискуссия | два значения в старых разделах; интернет не следует из частей | «общественная беседа» с уточнением контекста, кандидат |

После пересмотра: **317** опубликованных записей: **43** формы рабочего ядра и **274** кандидата. Эти числа отражают редакционную классификацию, а не подтверждённое число действительно универсальных слов.

## Правила редакции

1. Новая словарная форма обязана соответствовать 17-буквенному алфавиту и иметь одно уникальное написание.
2. Для многозначной формы значения перечисляются явно; отдельные противоречащие записи не допускаются.
3. Форма с дефисом является кандидатом и должна соответствовать модели «уточнение — главная основа».
4. Существительное с качеством пишется раздельно: `doma bona`, `soma mini`.
5. Кандидат получает статус `core` только после формальной редакционной процедуры; даже после этого он не считается международно подтверждённым.
6. Удаление/замена всегда документируется в журнале, чтобы старые тексты можно было интерпретировать.

## Автоматические проверки

`npm run validate` проверяет уникальность и графику слов, статус, наличие корней сложных слов, целостность статей, ссылок и всех примеров новой спецификации. Это **не** доказывает семантическую правильность или универсальную изучаемость.
